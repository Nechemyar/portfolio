Reel image-sequence takes (captured 2026-10-28, scripts/capture-seq.mjs in sumi-reel)
=====================================================================================

Format: 2880x1800 (1440x900 CSS at deviceScaleFactor 2), 30 fps, H.264 CRF 16, yuv420p.
No cursor is drawn. <take>.cursor.json has per-frame {f, x, y, down, scrollY} in CSS px
(multiply by 2 for frame pixels), plus "marks" (the action times listed below).

How it was captured (deterministic, not screen recording):
- Playwright's fake clock, paused, so JS time (rAF, timers, GSAP, counters) only moves when
  stepped. Each frame steps exactly 1/30 s.
- Every CSS animation, CSS transition and element.animate() in every frame/iframe is paused
  and seeked to (virtual time - time first seen). Finished ones are finish()ed so the page's
  own chaining (animationend / .finished) still runs.
- The mouse is the real Playwright mouse (hover, drag, press-and-hold all behave as for a
  user), eased, at most ~60 CSS px per frame.
- Each take starts with 0.5 s of still frames. Every take was checked frame by frame on
  contact sheets: the totals roll, the rows fade, the gauge segments draw in, the cards rise,
  and the hold fill grows.

   The page is pre-scrolled so the calculator fills the frame. The "Pricing" heading above

2. clinical-team.mp4 (9.5 s). clinicalassessments.co.uk/team/ (Meet The Team)
   0.0  still at the top of the page
   0.5  smooth scroll down 620 px (2.6 s). The 3-card grid glides up into view (Elementor fadeInUp)
   5.1  cursor arrives on Dr. Ruth M. Deutsch: grey panel fades in (0.2 s), photo scales (0.5 s)
   7.6  moves to Rochelle Silbiger. The first card eases back and the second animates in
   9.5  end
   The cursor starts in the left margin so its path never brushes the other cards.
   SURPRISING: on the live site the grids' fadeInUp fires on page load, because the second
   grid's top edge sits at y=874, just inside a 900 px tall window. So a normal scroll never
   shows the glide. For these takes the grids below the first one were put back into their
   pre-reveal state (elementor-invisible), and an IntersectionObserver adds Elementor's own
   "animated fadeInUp" classes when they enter the view. The animation is the site's real CSS.
   Only the trigger moment is ours.

Side effects: none. Nothing was submitted, booked or sent. Settle ?demo makes its own
POST /api/suggest calls on load (AI reply suggestions, the same as in the earlier takes),
and clinicalassessments sends Google Analytics beacons. Each take used a fresh browser
context, so the demo state starts clean every time.
